# SIGNAL360 Sprint 02 — Zero-capital deployment checklist

## Run the prototype
1. Extract SIGNAL360_Sprint02.zip.
2. Open SIGNAL360/index.html in a modern browser.
3. Select a demo role in the top-right selector.
4. Search public demo profiles.
5. Open Building Intelligence and AI Insights.
6. Submit a sample verification. It is stored locally and is not publicly published.

## Publish a no-cost demo
1. Create a GitHub account if needed.
2. Create a repository named signal360-demo.
3. Upload index.html.
4. Enable GitHub Pages in repository settings.
5. Share the resulting demo URL with interviewees.
6. Do not upload real personal data, sensitive network details or confidential customer information.

A static-hosted demo is not the production platform. Browser localStorage is not a secure database and does not sync between users/devices.

## Before accepting real customer data
- Set up a managed database and authentication.
- Enable row-level security on every private table.
- Create a curated public view with safe fields only.
- Add tenant isolation and role checks on the server.
- Add private evidence storage, audit events, backups and deletion workflows.
- Add privacy notice, consent/permission records and data retention policy.
- Test access controls with separate user accounts.
- Conduct security review and verify applicable Kenya data protection obligations.

## Founder validation script
Ask property managers, ISPs and technicians:
1. How do you currently establish whether a building can be connected?
2. What information is most often missing or inaccurate?
3. What does a failed or delayed site visit cost you?
4. Who owns or can authorise access to this information?
5. Would a verified building readiness report save time or money?
6. What would you pay for, and who approves that spend?
7. What would make you distrust this platform?

Do not lead respondents by telling them the idea is revolutionary. Seek evidence that they have the problem and budget.
